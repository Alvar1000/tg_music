# Лекция 4. Клавиатуры и callback_data

**Цель:** разобрать inline-клавиатуры — как они устроены, как собираются вручную и
через `InlineKeyboardBuilder`, и, главное, как проектировать `callback_data`: это
негласный «протокол» между кнопкой и хендлером, у которого есть жёсткий лимит.

**Нужно заранее:** [Лекция 3](03-routers-handlers-filters.md) (фильтры `F.data`,
`callback_query`).

---

## 1. Два вида клавиатур в Telegram (и почему здесь только inline)

В Telegram есть две клавиатуры:

- **Reply-клавиатура** — заменяет системную клавиатуру кнопками; нажатие шлёт
  *обычное текстовое сообщение* с подписью кнопки.
- **Inline-клавиатура** — кнопки **под конкретным сообщением**; нажатие шлёт
  `callback_query` с заранее заданной `callback_data` (либо открывает URL).

Проект целиком построен на **inline**. Причина в модели взаимодействия: бот — это
сменяющие друг друга экраны (меню → раздел → назад), и inline-кнопки позволяют
**редактировать то же самое сообщение**, превращая его в новый экран, не засоряя
чат (лекция 9). Reply-клавиатура так не умеет — она про ввод текста, а не про
навигацию по экранам.

Все клавиатуры собраны в одном модуле — `keyboards/kb.py`. Это сознательно: там же
живёт и «карта» всех `callback_data`. Один источник правды и для кнопок, и для
строк коллбэков.

---

## 2. Анатомия inline-клавиатуры

Клавиатура — это `InlineKeyboardMarkup` со списком рядов, каждый ряд — список
кнопок (`InlineKeyboardButton`). Самый явный способ — собрать вручную. Гейт
подписки (`gate_kb`):

```python
def gate_kb(channel_url: str) -> InlineKeyboardMarkup:
    """Экран-гейт: подписаться и перепроверить подписку."""
    return InlineKeyboardMarkup(inline_keyboard=[
        [InlineKeyboardButton(text="📢 Подписаться", url=channel_url)],
        [InlineKeyboardButton(text="✅ Я подписался", callback_data="check_sub")],
    ])
```

`inline_keyboard` — это **список списков**: внешний — ряды сверху вниз, внутренний —
кнопки слева направо. Здесь два ряда по одной кнопке. И сразу видно фундаментальное
различие двух типов кнопок:

- **URL-кнопка** (`url=...`) — открывает ссылку. Никакого апдейта боту не шлёт.
  Так сделана «Подписаться»: она ведёт на канал.
- **Callback-кнопка** (`callback_data=...`) — шлёт боту `callback_query` со строкой
  `"check_sub"`. Её ловит хендлер `@router.callback_query(F.data == "check_sub")`
  (лекция 3).

То есть `callback_data` кнопки и фильтр `F.data` хендлера — это **две стороны
одного контракта**. Кнопка says «check_sub», хендлер слушает «check_sub». Если их
рассинхронить — кнопка перестанет работать (провалится в fallback). Именно поэтому
ценно держать все коллбэки в одном файле.

## 3. Клавиатуры — это функции, а не константы

Каждая клавиатура в `kb.py` — **функция**, возвращающая разметку, а не глобальная
константа. Например, главное меню:

```python
def main_menu_kb() -> InlineKeyboardMarkup:
    return InlineKeyboardMarkup(inline_keyboard=[
        [InlineKeyboardButton(text="🎵 Плейлист дня", callback_data="menu_playlist")],
        [InlineKeyboardButton(text="🎲 Рандомный факт", callback_data="menu_fact")],
        [InlineKeyboardButton(text="🧠 Тесты", callback_data="menu_tests")],
        [InlineKeyboardButton(text="📅 Мероприятия", callback_data="menu_events")],
        [InlineKeyboardButton(text="💬 Общение", callback_data="menu_chat")],
    ])
```

Почему функция, а не `MAIN_MENU = InlineKeyboardMarkup(...)` на уровне модуля? Две
причины:

1. **Динамические клавиатуры.** Часть клавиатур строится **из данных** — кнопки
   вариантов теста, кнопки выбора в квесте. Их в принципе нельзя задать константой,
   они зависят от контента (см. раздел 5).
2. **Свежий объект на каждый показ.** Возвращать новую разметку каждый раз
   безопаснее, чем переиспользовать общий мутабельный объект.

Ещё приём — переиспользование общих кусков. Кнопка «назад в меню» нужна почти
везде, поэтому вынесена:

```python
def _back_button() -> InlineKeyboardButton:
    return InlineKeyboardButton(text="⬅ В меню", callback_data="go_menu")

def back_to_menu_kb() -> InlineKeyboardMarkup:
    return InlineKeyboardMarkup(inline_keyboard=[[_back_button()]])

def link_kb(text: str, url: str) -> InlineKeyboardMarkup:
    """Кнопка-ссылка + возврат в меню."""
    return InlineKeyboardMarkup(inline_keyboard=[
        [InlineKeyboardButton(text=text, url=url)],
        [_back_button()],
    ])
```

`_back_button()` — приватный помощник (подчёркивание = «для внутреннего
пользования»). Соберите кнопку один раз — используйте в десятке клавиатур. Меняете
текст «В меню» на «Назад» — правка в одном месте.

## 4. `InlineKeyboardBuilder`: когда кнопок много или они из цикла

Когда кнопок фиксированное небольшое число, удобен литерал списка (как в меню).
Но когда кнопки генерируются в цикле, аккуратнее использовать
`InlineKeyboardBuilder`. Классический пример — 12 знаков зодиака:

```python
from aiogram.utils.keyboard import InlineKeyboardBuilder

def zodiac_kb() -> InlineKeyboardMarkup:
    """12 кнопок со знаками зодиака, по 2 в ряд (callback zodiac:<индекс>)."""
    builder = InlineKeyboardBuilder()
    for i, sign in enumerate(ZODIAC_SIGNS):
        builder.button(text=f"{ZODIAC_EMOJI[sign]} {sign}", callback_data=f"zodiac:{i}")
    builder.adjust(2)            # 12 знаков -> 6 рядов по 2
    builder.row(_back_button())  # кнопка «В меню» отдельным рядом
    return builder.as_markup()
```

Что делает билдер:

- `builder.button(...)` добавляет кнопки **потоком**, не думая о рядах.
- `builder.adjust(2)` затем **раскладывает** уже добавленные кнопки по 2 в ряд.
  Одна цифра управляет всей сеткой: `adjust(2)` → сетка 2×6; хотите 3 в ряд —
  поменяйте на `adjust(3)`. Это сильно удобнее, чем вручную нарезать список
  списков.
- `builder.row(_back_button())` добавляет **отдельный** ряд (целиком), который под
  `adjust` не попадает, — кнопка «В меню» всегда одна на всю ширину снизу.
- `as_markup()` превращает билдер в готовый `InlineKeyboardMarkup`.

Тот же приём — в клавиатуре вариантов теста на стиль, только `adjust(1)` (по одной
кнопке в ряд, потому что тексты ответов длинные):

```python
def style_options_kb(options: list) -> InlineKeyboardMarkup:
    builder = InlineKeyboardBuilder()
    for i, opt in enumerate(options):
        builder.button(text=opt["text"], callback_data=f"style_ans:{i}")
    builder.button(text="⬅ В меню", callback_data="go_menu")
    builder.adjust(1)            # по одной кнопке в ряд (тексты длинные)
    return builder.as_markup()
```

**Правило выбора:** фиксированный небольшой набор → литерал списка (нагляднее);
кнопки в цикле / из данных → `InlineKeyboardBuilder` + `adjust`.

## 5. callback_data — это протокол. И у него лимит 64 байта

Самая важная инженерная тема лекции. `callback_data` — короткая строка, которую
кнопка отправляет боту при нажатии. По сути это **команда**, которую хендлер
расшифровывает. У строки жёсткое ограничение Telegram: **максимум 64 байта**
(именно байта — для кириллицы это вдвое меньше символов в UTF-8).

В проекте сложился аккуратный «протокол» коллбэков. Он даже задокументирован прямо
в шапке `kb.py`:

```
check_sub                 — перепроверить подписку (гейт)
go_menu                   — вернуться в главное меню
menu_playlist / menu_fact / menu_chat / menu_tests / menu_events — пункты меню
test_zodiac / test_style / quest_concert — выбор/перезапуск теста или квеста
zodiac:<индекс>           — выбранный знак зодиака (0..11)
style_ans:<индекс>        — выбранный вариант ответа в тесте на стиль
quest:<id_узла>           — переход к следующему узлу квеста
```

Видны два вида коллбэков:

- **Статические** — фиксированная строка-действие: `go_menu`, `menu_fact`,
  `test_style`. Хендлер ловит точным `F.data == "..."`.
- **Параметрические** — `префикс:параметр`. Хендлер ловит по префиксу
  (`F.data.startswith("zodiac:")`) и достаёт параметр из строки.

Двоеточие как разделитель — простая, читаемая конвенция. Разбор параметра — обычный
`split`:

```python
# handlers/tests.py
index = int(callback.data.split(":")[1])         # "zodiac:7" -> 7
option_index = int(callback.data.split(":")[1])  # "style_ans:2" -> 2
next_node = callback.data.split(":", 1)[1]       # "quest:S_NEXT" -> "S_NEXT"
```

Обратите внимание на `split(":", 1)` в случае квеста: ограничение «максимум одно
разбиение» защищает на случай, если id узла сам содержит двоеточие. Для индекса
зодиака это не нужно (там только число), но привычка полезная.

### 5.1. Трюк с индексом вместо названия

Почему знак зодиака едет в коллбэке как **число** (`zodiac:7`), а не как название
(`zodiac:Скорпион`)? Из-за лимита 64 **байта**. «Скорпион» в UTF-8 — это 16 байт, и
если бы id узлов или названия были длиннее, можно было упереться в лимит. Число —
всегда 1–2 байта. Поэтому:

```python
# kb.py: канонический порядок — индекс едет в callback_data
ZODIAC_SIGNS = [
    "Овен", "Телец", "Близнецы", "Рак", "Лев", "Дева",
    "Весы", "Скорпион", "Стрелец", "Козерог", "Водолей", "Рыбы",
]
# кнопка: callback_data=f"zodiac:{i}"
```

```python
# tests.py: по индексу восстанавливаем название
index = int(callback.data.split(":")[1])
sign = ZODIAC_SIGNS[index]
```

Список `ZODIAC_SIGNS` — это и есть «таблица соответствия»: индекс в коллбэке → имя
по позиции. **Важное следствие:** порядок в этом списке нельзя менять задним
числом, иначе старые кнопки в старых сообщениях будут указывать на другой знак. Об
этом прямо предупреждает комментарий в коде: «Индекс в этом списке едет в
callback_data».

### 5.2. Влияние лимита на контент квеста

Лимит 64 байта — не абстракция, он диктует правила редактору контента. В квесте
`callback_data` имеет вид `quest:<id_узла>`, где `<id_узла>` берётся прямо из
`quest_concert.json`. Поэтому в README проекта явно написано держать id узлов
**короткими** (`S0`, `S_NEXT`, `ENDING_BAD`), а не писать туда длинные
человекочитаемые имена. Архитектурное ограничение Telegram протекает в формат
данных — это нормально, и об этом важно помнить при проектировании коллбэков.

## 6. Карта клавиатур проекта

Чтобы видеть всю навигацию, вот какие функции `kb.py` какие экраны обслуживают:

| Функция | Где используется | Ключевые callback_data |
|---------|------------------|------------------------|
| `gate_kb(url)` | гейт подписки | `check_sub` (+ URL на канал) |
| `main_menu_kb()` | главное меню | `menu_playlist/fact/tests/events/chat` |
| `back_to_menu_kb()` | заглушки, пустые разделы | `go_menu` |
| `link_kb(text,url)` | плейлист, чат | URL + `go_menu` |
| `fact_kb()` | после факта | `menu_fact` (ещё факт) + `go_menu` |
| `tests_menu_kb()` | меню тестов | `test_zodiac/test_style/quest_concert` |
| `zodiac_kb()` | выбор знака | `zodiac:0..11` + `go_menu` |
| `style_options_kb(options)` | вопрос теста | `style_ans:i` + `go_menu` |
| `quest_choices_kb(choices)` | узел квеста | `quest:<id>` + `go_menu` |
| `*_result_kb()` / `quest_end_kb()` | экраны результата | повтор теста + `go_menu` |

Заметьте повторяющийся паттерн: почти в каждой клавиатуре последней кнопкой —
возврат в меню (`go_menu`). Навигация всегда оставляет путь назад; пользователь не
может «застрять» на экране без выхода.

## 7. Частые грабли

- **Превышение 64 байт.** Длинный `callback_data` (особенно с кириллицей) Telegram
  не примет. Кодируйте параметры компактно — индексом или коротким id, как здесь.
- **Рассинхрон кнопки и хендлера.** Поменяли `callback_data` в `kb.py`, забыли
  фильтр в хендлере — кнопка молча уходит в fallback. Держать всё в одном модуле и
  именовать единообразно — защита от этого.
- **URL-кнопка не шлёт callback.** Если ждёте от кнопки реакцию хендлера, у неё
  должен быть `callback_data`, а не `url`. URL — только «открыть ссылку».
- **Перестановка `ZODIAC_SIGNS` / переименование id узлов.** Ломает кнопки в уже
  отправленных сообщениях. Индексы и id — часть «протокола», обращайтесь с ними как
  с версионируемым API.

---

### Итоги лекции

- Проект — на inline-клавиатурах: они позволяют редактировать сообщение в новый
  экран (навигация), а нажатие шлёт `callback_query`.
- Клавиатура = `InlineKeyboardMarkup` со списком рядов; кнопка бывает **URL** или
  **callback**. Все клавиатуры — функции в `kb.py`, общие куски вынесены
  (`_back_button`).
- `InlineKeyboardBuilder` + `adjust(n)` удобны, когда кнопки генерируются циклом
  или из данных; литерал списка — для фиксированных наборов.
- `callback_data` — это протокол между кнопкой и хендлером с лимитом **64 байта**;
  отсюда `префикс:индекс`, трюк с `ZODIAC_SIGNS` и требование коротких id узлов
  квеста.
